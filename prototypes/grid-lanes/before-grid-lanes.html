Before Grid Lanes: CSS Columns

This is how developers created masonry-like layouts before display: grid-lanes arrived. Using CSS column-count, browsers automatically distribute items into columns. Note the trade-offs: items flow vertically down one column before moving to the next, and tab order follows visual layout rather than source order.

CSS Columns

The primary pre-Grid Lanes approach. The column-count property tells the browser how many columns to create, and items are distributed top-to-bottom within each column.

Vertical Flow Issue

Items flow down the first column completely before wrapping to the next column. This can create awkward reading patterns. With 3 items and 3 columns, all items end up in their own column.

column-gap

Control spacing between columns with column-gap. This was the main way to add breathing room before the modern gap property in Grid.

column-fill

Set column-fill: auto to make columns progressively narrower if content doesn't fill them evenly. The default column-fill: balance tries to make all columns equal height.

Spanning Elements

Use break-inside: avoid to prevent cards from being split across columns. However, making an item span all columns with column-span: all requires taking it out of the flow entirely.

No Responsive Lanes

You must use media queries to change column-count at different breakpoints. Grid Lanes' repeat(auto-fill, ...) adapts automatically without explicit breakpoints.

Tab Order Problem

Screen readers and keyboard navigation follow the visual column layout, not the HTML source order. This breaks semantic meaning and accessibility — users tabbing through get sent to unexpected places.

JavaScript Masonry Libraries

Before CSS Columns matured, the standard solution was JavaScript libraries like Masonry.js. These measure each item's height, calculate the shortest column, and update positions — expensive work in the browser's main thread.

The Balancing Act

Columns try to "balance" height across all columns, but content is unpredictable. Five tall items and one short one results in uneven heights. No fine-grained control over placement algorithm.

Why Grid Lanes is Better

Grid Lanes brings masonry layout to CSS Grid with automatic flow, predictable tab order that matches source, responsive column counts, no JavaScript needed, and fine control over the placement algorithm via flow-tolerance. It's the proper platform solution to a problem developers have struggled with for over a decade.

Performance Trade-offs

CSS Columns don't require JavaScript, but they're calculated during layout. Large content changes force the browser to recalculate all column heights and reflow everything. Grid Lanes puts this burden on the CSS engine, not JS.
